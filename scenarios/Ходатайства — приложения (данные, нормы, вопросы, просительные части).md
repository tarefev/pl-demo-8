## Приложение 1. Модель данных доказательства

### 1.1. Что не так с текущей моделью

Сейчас доказательство в карточке дела — строка текста: `'Показания Свидетеля №1 —
сотрудника магазина «Продукты 24»'`. Для апелляционной жалобы этого хватало: строка
подставлялась в основание довода. Для ходатайств не хватает принципиально.

Ходатайство о признании доказательства недопустимым без указания тома и листов дела
суд рассматривать не обязан — он не ищет доказательство за защитника. Ходатайство о
приобщении без указания способа получения отклоняется как не отвечающее статье 86
части 3 УПК РФ. Ходатайство об исключении требует знать, каким процессуальным
действием доказательство получено, — от этого зависит применимая причина
недопустимости.

Строка ничего этого не хранит.

### 1.2. Предлагаемая структура

```js
{
  id: 'ev-1',

  // Что это
  kind: 'testimony',        // вид доказательства (см. таблицу ниже)
  title: 'Показания свидетеля Ивановой И. И.',
  description: '',          // при необходимости — краткое содержание

  // Где искать в деле
  volume: 2,                // том
  sheets: '45-47',          // листы дела (строкой: «45», «45-47», «45, 48»)
  inCase: true,             // приобщено к материалам дела

  // Откуда взялось
  obtainedBy: 'investigation',  // способ получения (см. таблицу ниже)
  obtainedAt: '12.03.2026',     // дата получения или составления
  source: 'Следователь СО ОМВД Петров П. П.',  // кем получено, от кого

  // Процессуальная привязка
  actionType: 'interrogation',  // каким действием получено (допрос, осмотр, обыск…)
  participants: [],             // кто участвовал: защитник, понятые, специалист

  // Для чего используется защитой
  proves: 'Хищение обнаружено только после его начала',  // что подтверждает
  lineIds: ['line-1'],          // линии защиты, которые опирается на него

  // Пороки (заполняется при работе с недопустимостью)
  defects: [
    { type: 'no-defender', note: 'Допрос проведён без защитника' }
  ],

  // Файлы
  attachments: [ { name: 'protokol.pdf', size: 240000 } ]
}
```

### 1.3. Справочники значений

**Вид доказательства** (`kind`) — по статье 74 части 2 УПК РФ:

| Значение | Отображение |
|---|---|
| `testimony-suspect` | Показания подозреваемого, обвиняемого |
| `testimony-victim` | Показания потерпевшего, свидетеля |
| `expert-opinion` | Заключение и показания эксперта |
| `specialist-opinion` | Заключение и показания специалиста |
| `material` | Вещественное доказательство |
| `protocol` | Протокол следственного или судебного действия |
| `document` | Иной документ |

**Способ получения** (`obtainedBy`) — определяет, какие ходатайства применимы:

| Значение | Отображение | Где важно |
|---|---|---|
| `investigation` | Получено следствием | Недопустимость, исключение |
| `court` | Получено в судебном заседании | Исключение |
| `advocate-request` | Адвокатский запрос | Приобщение (ст. 86 ч. 3 п. 1) |
| `survey` | Опрос лица с его согласия | Приобщение (ст. 86 ч. 3 п. 2) |
| `client` | Представлено доверителем | Приобщение (ст. 86 ч. 3 п. 3) |
| `specialist` | Заключение специалиста по инициативе защиты | Приобщение, экспертиза |

**Пороки** (`defects[].type`) — соответствуют группам причин недопустимости из § 4
основного документа: `violence`, `provocation`, `unauthorized`, `no-rights`,
`no-defender`, `expert-order`, `no-signature`, `copy-instead`, `hearsay`,
`irrelevant`, `unreliable`, `unclear`, `contradictory`.

### 1.4. Как переезжаем со строк

Существующие данные — массив строк. Миграция без потери: строка становится объектом,
где `title` — сама строка, `kind` угадывается по ключевым словам («показания» →
`testimony-victim`, «протокол» → `protocol`, «заключение» → `expert-opinion`,
«справка», «выписка» → `document`), остальные поля пустые и помечаются как требующие
заполнения.

Там, где доказательство используется в ходатайстве и незаполненного поля не хватает,
визард запрашивает его точечно — том и листы для недопустимости, способ получения для
приобщения, — а не заставляет заполнять карточку целиком.

### 1.5. Где какое поле обязательно

Не все поля нужны всегда — требовать заполнения целиком значит убить скорость.
Обязательность возникает точечно, в момент, когда поле реально нужно документу.

| Поле | Обязательно для |
|---|---|
| `title` | Всегда |
| `kind` | Приобщение (влияет на формулировку), недопустимость (влияет на набор причин) |
| `volume`, `sheets` | Недопустимость, исключение, допрос эксперта по заключению, любое ходатайство со ссылкой на материалы дела |
| `obtainedBy` | Приобщение (ст. 86 ч. 3), недопустимость (определяет применимые пороки) |
| `obtainedAt` | Недопустимость при доводе о нарушении сроков; приобщение при опросе лица |
| `actionType` | Недопустимость: от вида действия зависит перечень нарушений процедуры |
| `proves` | Приобщение, привязка к доводу в конструкторе |
| `inCase` | Приобщение: если уже в деле, визард предупреждает, что ходатайство не требуется |

### 1.6. Что это даёт помимо ходатайств

Расширенная модель закрывает несколько задач разом. Появляется возможность
автоматически собирать приложение к документу («копия протокола допроса, т. 2 л. д.
45–47»). Появляется проверка полноты: доказательство без тома и листов подсвечивается
в карточке, а не в момент, когда адвокат уже пишет ходатайство. Появляется связь
«доказательство — линия защиты», которая работает в обе стороны: из линии видно, чем
она подтверждается, из доказательства — на что оно работает.

## Приложение 3. Типовые вопросы эксперту

Формулировки, предлагаемые визардом на шаге «вопросы эксперту». Адвокат правит и
дополняет. Общее правило: вопрос ставится в пределах компетенции эксперта, не требует
правовой оценки и допускает проверяемый ответ.

### 3.1. Правила, встроенные в подсказки

Эксперт не решает правовых вопросов: спрашивать «имеются ли в действиях признаки
состава преступления» бессмысленно, такой вопрос отклоняется. Вопрос должен быть
конкретным и допускать однозначный ответ. Порядок вопросов — от общего к частному.
Полезно завершать блок открытым вопросом о значимых обстоятельствах, обнаруженных
экспертом самостоятельно.

### 3.2. Судебно-медицинская экспертиза (живого лица)

1. Какие телесные повреждения имеются у [ФИО], каковы их характер, локализация и
   механизм образования?
2. Какова давность образования каждого из обнаруженных повреждений?
3. Какова степень тяжести вреда, причинённого здоровью, по каждому повреждению?
4. Могли ли повреждения образоваться при обстоятельствах, указанных [лицом] в
   показаниях от [дата]?
5. Могли ли повреждения образоваться в результате падения с высоты собственного роста?
6. Имеются ли признаки, характерные для самоповреждения?

### 3.3. Судебно-психиатрическая экспертиза

1. Страдал ли [ФИО] в момент совершения деяния психическим расстройством?
2. Мог ли [ФИО] осознавать фактический характер и общественную опасность своих
   действий и руководить ими в момент деяния?
3. Страдает ли [ФИО] психическим расстройством в настоящее время?
4. Нуждается ли [ФИО] в применении принудительных мер медицинского характера?
5. Может ли [ФИО] по своему психическому состоянию участвовать в следственных
   действиях и судебном заседании?

### 3.4. Психолого-психиатрическая (комплексная)

1. Имеются ли у [ФИО] индивидуально-психологические особенности, оказавшие
   существенное влияние на поведение в исследуемой ситуации?
2. Находился ли [ФИО] в момент деяния в состоянии аффекта или ином выраженном
   эмоциональном состоянии?
3. Способен ли [ФИО] правильно воспринимать обстоятельства, имеющие значение для дела,

### 3.5. Автотехническая экспертиза

3. Каков механизм дорожно-транспортного происшествия?
4. Какими пунктами Правил дорожного движения должен был руководствоваться водитель

5. Соответствуют ли повреждения транспортных средств заявленному механизму
   происшествия?
6. Каково техническое состояние транспортного средства и находится ли неисправность
   в причинной связи с происшествием?

### 3.6. Почерковедческая экспертиза

1. Кем — [ФИО] или иным лицом — выполнена подпись от имени [ФИО] в [документ]?

4. Выполнены ли подписи в нескольких документах одним лицом?

### 3.7. Техническая экспертиза документов

1. Соответствует ли дата составления документа дате, указанной в нём?

3. Каким способом изготовлен документ (бланк, оттиск печати, подпись)?
4. Нанесён ли оттиск печати печатью [организации], образцы которой представлены?

### 3.8. Дактилоскопическая экспертиза

1. Имеются ли на представленных объектах следы рук, пригодные для идентификации?
2. Оставлены ли следы рук [ФИО]?
3. Какой рукой и какими пальцами оставлены следы?
4. Какова давность образования следов (при наличии методики)?

### 3.9. Баллистическая экспертиза

1. Является ли представленный предмет огнестрельным оружием, к какому виду относится?
2. Пригоден ли предмет для производства выстрелов?
3. Не выстреляна ли пуля (гильза) из представленного оружия?
4. Возможен ли выстрел из данного оружия без нажатия на спусковой крючок?
5. С какого расстояния произведён выстрел?

### 3.10. Экспертиза наркотических средств (химическая)

3. Каково содержание наркотически активного компонента?
4. Имеют ли вещества, изъятые в разных местах, общий источник происхождения?

### 3.11. Судебно-бухгалтерская и экономическая экспертиза

1. Соответствуют ли данные бухгалтерского учёта первичным документам за период с

2. Каков размер денежных средств, поступивших и израсходованных [организацией] за

3. Подтверждается ли документально размер ущерба, указанный в обвинении?
4. Имеются ли признаки искажения бухгалтерской отчётности и в чём они выражаются?

### 3.12. Товароведческая экспертиза

1. Какова рыночная стоимость [предмет] на дату [дата]?
2. Каково фактическое состояние предмета, имеются ли следы эксплуатации и износа?
3. Соответствует ли заявленная стоимость среднерыночной для аналогичных товаров?

### 3.13. Лингвистическая экспертиза

### 3.14. Фоноскопическая экспертиза

### 3.15. Компьютерно-техническая экспертиза

## Приложение 4. Шаблоны просительной части

Общие правила, по которым построены все шаблоны.

Просьба формулируется одним действием и не пересказывает мотивировку. Указывается
конкретный предмет — доказательство с томом и листами, документ с наименованием,
лицо с данными. Если действие требует срока или порядка, он указывается прямо.
Последним пунктом идёт просьба уведомить о результатах рассмотрения — по статье 122
УПК РФ решение оформляется постановлением, и защитник вправе его получить.
Перечисление приложений в просительную часть не входит: они идут отдельным разделом.

Обозначения: `{…}` — подставляется из карточки дела или ответов визарда.

### 4.1. Ознакомление с материалами дела

*Следствие, до окончания:*
> 1. Ознакомить защитника {ФИО защитника} с материалами уголовного дела
>    № {номер}, а именно: {перечень выбранных материалов}.
> 2. Предоставить возможность снять копии с указанных материалов, в том числе с
>    помощью технических средств.
> 3. О принятом решении уведомить защитника в порядке ст. 122 УПК РФ.

*Следствие, по окончании (ст. 217):*
> 1. Ознакомить обвиняемого {ФИО} и его защитника со всеми материалами уголовного
>    дела № {номер} в полном объёме без ограничения во времени.
> 2. Предоставить возможность снять копии со всех материалов дела, в том числе с
>    помощью технических средств.

*Суд:*
> 1. Предоставить защитнику возможность ознакомиться с материалами уголовного дела
>    № {номер}, а также с протоколом и аудиозаписью судебного заседания от {дата}.
> 2. Предоставить возможность снять копии, в том числе с помощью технических средств.

### 4.2. Признание доказательства недопустимым (следствие)

## Приложение 5. Приоритет реализации

Если внедрять не всё сразу, порядок такой.

Сначала — модель данных доказательства с миграцией: без неё половина ходатайств
собирается некорректно, а переделывать потом дороже.

Затем — справочник норм: он нужен всем визардам и не зависит от интерфейса.

Затем — шаблоны просительной части: без них документ не собрать вовсе.

Вопросы эксперту — в последнюю очередь: они нужны одному визарду из шестнадцати и до
их появления шаг заполняется вручную.

## Приложение 6. Шаблоны партнёра-адвоката: что внедрено

Партнёр передал бумажные шаблоны по пятнадцати ходатайствам. Тексты приведены к ним
в `js/motion-defs.js` и `js/motion-wizard.js`. Общая рамка одинакова во всех:

1. **Шапка** — адресат, номер дела, защитник с реквизитами (регистрационный номер,
   удостоверение, адрес, телефон), в чьих интересах и по какому обвинению.
   Для ходатайства о мере пресечения добавляется строка о действующей мере.
2. **Два вводных абзаца** (`motionIntro`) — где находится дело и кто осуществляет защиту
   на основании ордера и соглашения.
3. **Предмет** — доказательство, заключение, мера, материалы: то, о чём ходатайство.
4. **Обоснование** — свободный текст адвоката (шаг визарда, при желании черновик от ИИ).
5. **Цитаты норм** (`NQ`) — полные формулировки статей, как в бумажных шаблонах,
   без сокращений; состав зависит от стадии и вида ходатайства.
6. **Просительная часть** — по пунктам шаблона, включая уведомление о принятом решении.
7. **Приложение** — документы по существу плюс ордер адвоката. Ордер не прилагается
   к ходатайству об исключении доказательства в суде: защитник уже участвует в деле.
8. **Дата и подпись** (`mwSignHtml`).

Что различается по стадии: адресат шапки, нормы (ст. 175 против ч. 2 ст. 252 при
переквалификации, ст. 88 против ст. 235 при недопустимости), объём материалов и
копирования при ознакомлении, состав просительной части.

Падежи и согласования, которые пришлось развести отдельно: суд в родительном
(«в производстве Киевского районного суда»), защитник в дательном («предоставить
защитнику Гусейнову»), меры пресечения в родительном и винительном («в виде
заключения под стражу» / «изменить на подписку о невыезде»), вид экспертизы в
винительном («назначить повторную судебную судебно-медицинскую экспертизу»),
статус осуждённого («осуждённого по ч. 1 ст. 161 УК РФ», а не «в совершении»).
